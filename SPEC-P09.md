## 1 Purpose

The self-paying data client: an agent that buys Nansen smart-money data with
USDC over x402 v2 on Monad — **no API key**. Native Rust flow (signer =
alloy). When this lands, `SmartMoneyContext` (P07) is fillable from real
purchases, with a spend ledger and a hard hourly budget.

**Live status:** the x402 payer wallet (`NANSEN_PAYER_KEY`) is still a
placeholder → the paid smoke (`test-nansen`) stays PENDING-WALLET; the free
`--check` leg (real 402 challenge parse) runs live NOW, and the full paid
flow is proven offline against the recorded challenges + an independent
EIP-712 oracle.

## 2 Ground truth (verified 2026-10-05/06)

- Recorded live 402s: `docs/evidence/p01-nansen-402*.json` (+
  `payment-required` base64 header on `.headers`). 8 rails per endpoint.
- **Monad rail (our target, exact bytes):** `{scheme:"exact",
  network:"eip155:143", asset:"0x754704Bc059F8C67012fEd69BC8A327a5aafb603",
  amount:"50000"|"10000", payTo:"0x93053f1e7A5eFEDa532Fe69CbbE43cBEc3A0F13f",
  maxTimeoutSeconds:300, extra:{name:"USDC", version:"2"}}`.
- x402 v2 PaymentPayload (base64 → `PAYMENT-SIGNATURE`):
  `{x402Version:2, resource:{…verbatim from the 402…}, accepted:{…the chosen
  rail VERBATIM…}, payload:{signature:"0x…", authorization:{from,to,value,
  validAfter,validBefore,nonce}}}` — strings as in the spec examples.
- EIP-3009 `TransferWithAuthorization` EIP-712: domain `{name, version}` from
  the rail's `extra`, `chainId` from CAIP-2 (`eip155:143` → 143),
  `verifyingContract` = asset. Types: `from address, to address, value
  uint256, validAfter uint256, validBefore uint256, nonce bytes32`.
  Signature: 65 bytes `0x…` (v ∈ {27,28}).
- Response settlement: `PAYMENT-RESPONSE: <base64 SettlementResponse>`
  `{success, transaction, network, payer}`; missing header ⇒ settlement None.
- Headers: retry with `PAYMENT-SIGNATURE` (V2); send `X-Payer-Address:
  <wallet>` on the INITIAL unpaid request (promo hook; not advertised —
  STUB-04).
- Endpoints (bodies: FACTS-confirmed `{"chains":["<chain>"]}` for
  smart-money; the others remain STUB-05 best-effort, pin them in tests and
  confirm at the first keyed/paid call): `/api/v1/smart-money/netflow`,
  `/api/v1/smart-money/holdings`, `/api/v1/perp-leaderboard` ($0.05 each);
  `/api/v1/profiler/perp-positions` ($0.01).

## 3 Modules (`crates/sentinel/src/nansen/`)

`mod.rs` (orchestrator) · `x402.rs` (wire + signer + flow) · `client.rs`

### 3.1 x402.rs — frozen surfaces (stubs = contract)

Types (serde, exact wire casing via `rename`):
`PaymentRequirements`, `PaymentRequired`, `ResourceInfo`, `Authorization`,
`ExactEvmPayload`, `PaymentPayload`, `SettlementResponse`; consts
`HEADER_PAYMENT_REQUIRED="payment-required"`, `HEADER_PAYMENT_SIGNATURE`,
`HEADER_PAYMENT_RESPONSE`.

- `PayerSigner::from_hex(0x-key) -> Result<Self>` (alloy
  `PrivateKeySigner`; `Debug` redacts — manual impl), `address() -> String`,
  `sign_authorization(&PaymentRequirements, &Authorization) -> Result<String>`
  (EIP-3009 typed-data hash + `sign_hash`; 65-byte `0x…` hex, v 27/28).
  Check the registry sources under `~/.cargo/registry/src/*/alloy-*` for the
  exact sol!/eip712 API; if `alloy::sol!` is unavailable with our feature
  set, hand-roll the EIP-712 struct hash (keccak256 over the type string +
  encoded fields) and document it.
- `select_rail(&PaymentRequired, network: &str) -> Result<&PaymentRequirements>`
  (scheme must be `exact`; missing ⇒ `Challenge`).
- `parse_payment_required(status, body, header_b64) -> Result<PaymentRequired>`:
  body JSON first; on failure decode the header (base64 STANDARD; tolerate
  no-pad); non-402 ⇒ `Challenge`.
- `build_authorization(&PaymentRequirements, payer, now_ms) -> Authorization`:
  `from`=payer, `to`=payTo, `value`=amount, `validAfter`=now−60s (skew),
  `validBefore`=now+maxTimeoutSeconds, `nonce`=`0x`+32 random bytes
  (`getrandom`).
- `cost_usd(amount: &str) -> Decimal` = amount / 10^6 (stable-rail
  assumption; documented).
- `encode_payload(&PaymentPayload) -> String` (base64) /
  `decode_payment_signature(b64) -> Result<PaymentPayload>`.
- `fetch_with_payment(http, url, body, signer, network, now_ms) -> Result<PaidResponse>`
  with `PaidResponse{body, settlement: Option<SettlementResponse>,
  cost_usd, rail_network}`: POST unpaid (JSON + `X-Payer-Address`) → 200
  pass-through (settlement None) | 402 → parse → select rail → build+sign
  → retry with both `X-Payer-Address` and `PAYMENT-SIGNATURE` → 200 with
  settlement from the header (tolerate absent) | ≠200 ⇒
  `NansenError::Retry{status}`. Never logs the key/signature (redaction).

### 3.2 client.rs

`netflow_body(chain)`, `holdings_body(chain)` = `{"chains":[chain]}`;
`leaderboard_body(market)` = `{"market":…}`; `perp_positions_body(addresses)`
= `{"addresses":[…]}` — the last three are STUB-05 best-effort (comment +
STUBS.md note). Parsers return `Option<Decimal>` scanning a documented
candidate key list (`net_flow_usd`, `netflow`, `net_flow`,
`total_net_flow`, …) — the winner is pinned by tests; update at the first
paid call.

### 3.3 cache.rs

`TtlCache{ttl_ms, entries}` — `get(&mut, key, now)`, `put(&mut, key, value,
now)`, `prune(&mut, now)`, `len()`; expiry inclusive (`now >= expiry` ⇒
miss). `pub fn key(endpoint, params: &Value) -> String` =
`"{endpoint}|{canonical-json(params)}"` (serde_json Value is BTreeMap ⇒
sorted, deterministic).

### 3.4 spend.rs

`SpendEntry{ts_ms, endpoint, cost_usd: String, tx_hash: Option<String>,
payer: Option<String>, network: Option<String>}` (serde);
`SpendLedger{path}` — `load()` (missing ⇒ empty), `append(&entry)`
(create dirs, one JSON line, append), `calls_since(now, window_ms)`,
`cost_since(now, window_ms)`. The ledger is the single source of truth for
the hourly budget.

### 3.5 mod.rs — orchestrator

`CallMeta{cost_usd, tx_hash, cached, endpoint}`; `NansenClient::new(&NansenConfig)
-> Result<Self>` (builds `PayerSigner` from `NANSEN_PAYER_KEY`, base_url,
`NANSEN_PAYMENT_NETWORK`, TTL, `NANSEN_MAX_CALLS_PER_HOUR`, ledger at
`data/nansen-spend.jsonl`); `with_ledger_path` (tests).

`call_endpoint(endpoint, body, now_ms)`:
1. cache hit ⇒ `(value, meta{cached:true, cost:0})` (NO budget spend).
2. budget: `ledger.calls_since(now, 3_600_000) >= max` ⇒
   `NansenError::Budget{spent, limit}`.
3. `fetch_with_payment` → append ledger entry (cost, tx, payer=signer addr,
   network) → cache put → `(value, meta)`.

`sm_netflow`, `perp_positions` wrappers. `smart_money_context(asset, chain,
now_ms) -> SmartMoneyContext` — **best-effort, never fails**: on any error
⇒ `SmartMoneyContext::unavailable(asset)` + `warn!`; on success fills
`netflow_24h`, `fetched_at_ms`, `total_cost_usd`, and sets `note =
Some("cross-venue smart-money signal as directional proxy (Nansen coverage
is not Perpl-specific)")` — the honesty requirement, also mirrored in the
README later.

## 7 Required tests

- `x402-core`: recorded-fixture parse (body from
  `p01-nansen-402-profiler-perp-positions.json` — assert the Monad rail's
  exact fields); header-base64 fallback decode; rail selection (match /
  missing network ⇒ Challenge / non-exact scheme skipped); payload encode →
  decode round-trip; authorization build (fields, value/amount echo,
  validBefore−validAfter == maxTimeoutSeconds, nonce 32 bytes, skew);
  **signature vector**: fixed key + fixed authorization ⇒ signature
  that (a) recovers to the signer via alloy recovery AND (b) equals the
  pinned hex an independent oracle computed (see §8); `cost_usd` table;
  wiremock flow: 402 (fixture headers+body) → assert the retry carries
  `PAYMENT-SIGNATURE` (decode + verify `accepted` = the Monad rail, `from` =
  payer) + `X-Payer-Address` → 200 with `PAYMENT-RESPONSE` (synthetic
  settlement) ⇒ `PaidResponse{settlement: Some, cost_usd 0.01}`; without
  the header ⇒ None; final 403 ⇒ `Retry{403}`; no key material in Debug.
- `endpoints`: bodies exact (`{"chains":["ethereum"]}`); cache — hit within
  TTL, miss at exactly expiry, prune; key determinism; ledger — append
  format (one line, fields), totals across windows, sliding-hour count,
  missing file ⇒ empty; budget boundary (N in window allowed, N+1 ⇒
  `Budget`).
- `orchestrator`: wiremock end-to-end — first call pays (ledger has 1 entry,
  meta.cached false), second call within TTL is cached (ledger still 1,
  cost 0); budget breach before any HTTP; `smart_money_context` fills fields
  on success incl. the proxy note; on 402-then-failure ⇒
  `unavailable` + never panics.
- Verifier (`tests/nansen_adversarial.rs`, black box): its own wiremock
  variants (malformed 402 JSON + valid header fallback; header with
  no-padding; duplicate rails; amount swapped after signing must NOT be the
  accepted one); **independent EIP-712 oracle**: Node + ethers 6.17 (already
  installed at `~/.hermes/cache/scratch/oracle`) recomputing the signature
  for the same fixed vector — the pinned expectation in the test comes from
  the oracle, not from our code (commit the oracle script under
  `tests/fixtures/nansen/eip712_oracle.js` with the exact invocation in
  comments); re-run of `cargo test -p sentinel --test brain_adversarial`
  stays green (regression gate); `test-nansen --check` binary presence
  (spawn with a short timeout is NOT required — print `--help`-ish usage
  path or assert arg parsing via a unit test in the bin).

## 2 Decision schema v3 (core `sentinel_core::types::Decision`)

```json
{"action":"HOLD|REDUCE|CLOSE|ADD_COLLATERAL|ESCALATE","market_id":32,
 "amount":"1.25"|null,"confidence":0.72,"urgency":"ROUTINE|ELEVATED|CRITICAL",
 "reason":"<=2 sentences grounded in provided data"}
```

- `DecisionAction` / `Urgency`: `SCREAMING_SNAKE_CASE` serde renames.
- `amount`: `Option<Decimal>`, **string on the wire** (`"1.25"`; `null`
  allowed; tolerant parse may also accept a JSON number).
- Parsing is **tolerant of unknown fields** (serde default — do NOT add
  `deny_unknown_fields`); missing required fields are a typed error.
- `Decision::validate(&self, allowed_markets: &[MarketId]) -> Result<(), String>`:
  `confidence` in `[0, 1]`; `market_id` present in `allowed_markets`;
  `amount` is `Some(> 0)` for `REDUCE` and `ADD_COLLATERAL`; for other
  actions `amount` is ignored (may be null).

## 3 Providers (`crates/sentinel/src/brain/providers.rs`)

- `RawCompletion { text: String, provider: String, model: String,
  prompt_tokens: Option<u32>, completion_tokens: Option<u32>, latency_ms: u64 }`.
- `#[allow(async_fn_in_trait)] pub trait Provider { async fn complete(&self,
  system: &str, user: &str) -> Result<RawCompletion>; fn name(&self) ->
  &'static str; }` (no `dyn`; generics only).
- `QwenProvider::new(&cfg.qwen)`: Bearer key; `POST {base}/chat/completions`;
  body `{model, messages:[system,user], max_tokens, temperature, response_format:{"type":"json_object"}}`
  — `json_mode` flag defaults **true**, `with_json_mode(bool)` override
  (first live run disables it if the endpoint rejects it; note in report).
  Temperature serialized as a JSON **number** (`Decimal::to_f64`).
  **One retry** on 5xx/timeout; never on 4xx. Timeout 60 s;
  `with_client(Client)` for tests. Structured `tracing::info!` per call:
  provider, model, latency_ms, prompt_tokens, completion_tokens, retried.
  HTTP errors → `BrainError::ProviderHttp{provider,status}`; missing/malformed
  `choices[0].message.content` → `BrainError::InvalidJson{provider}`.
- `KimiProvider::new(&cfg.kimi)`: same shape; `json_mode` defaults **false**;
  `max_tokens = 4000`, `temperature = 0.1` constants (KimiConfig has neither).
- `MockProvider`: `VecDeque<Result<RawCompletion, SentinelError>>` behind a
  `Mutex`; `MockProvider::canned(texts)`; records every `(system, user)` call
  pair in order (`calls()`); empty queue → `AllProvidersFailed{last:"mock queue exhausted"}`.

## 4 Parser (`brain/parser.rs`)

- `strip_thinking(raw) -> &str`: if a `</think…>`-style closing tag exists
  (case-insensitive `</think`, any suffix up to `>`), return the slice after
  the **last** occurrence's `>`; else the whole text.
- `extract_balanced_object(raw) -> Option<&str>`: first `{…}` that balances,
  **string-aware** (quotes, backslash escapes); braces inside strings do not
  count.
- `parse_decision(raw, allowed_markets) -> Result<Decision, ParseError>`:
  strip → extract → `serde_json::from_str` (unknown fields ignored) →
  `Decision::validate`. `ParseError::{NoObject, Json{detail}, Validation{detail}}`
  (Display implemented; engine maps NoObject/Json → `InvalidJson{provider}`,
  Validation → `InvalidDecision{detail}`).
- `repair_nudge(bad_raw) -> String`: the single follow-up user message —
  `"Return ONLY the JSON object matching this schema: {SCHEMA_DOC}. Previous
  output was: <bad_raw>"`; `pub const SCHEMA_DOC` = the §2 JSON skeleton with
  placeholders (shared with prompts).
- Unit tests must cover **at least**: prose-wrapped JSON, markdown fences,
  thinking-trace preamble (incl. `</thinking>` variant), trailing commas
  (reject), string-with-braces, nested objects, escaped quotes, empty
  response, refusal text, truncated JSON, two objects (first wins),
  amount-as-number tolerance, unknown fields ignored, missing required field.

## 5 Prompts (`brain/prompts.rs`)

- `pub const PROMPT_VERSION: &str = "v3.0";` logged with every consult.
- `system_prompt()` — risk-guardian role; isolated-margin semantics; tier
  thresholds (soft/warn/hard read from no config — the numeric thresholds go
  in the USER block so the system text stays static); available actions incl.
  ESCALATE = needs-human; strict JSON schema reference; grounding rule (cite
  only numbers present in the user message); capital-preservation bias (in
  Orange, when uncertain between HOLD and REDUCE, prefer REDUCE); never
  recommend increasing exposure.
- Serde-able summary types (Serialize+Deserialize):
  `PolicySummary { market_allowlist: Vec<MarketId>, max_order_size_usd: Decimal,
  require_approval_above_usd: Decimal, daily_actions_left: u32 }`;
  `SmartMoneyContext { asset: String, netflow_24h: Option<Decimal>,
  holdings_delta: Option<Decimal>, long_short_ratio: Option<Decimal>,
  top_traders_net_bias: Option<String>, fetched_at_ms: Option<u64>,
  total_cost_usd: Option<Decimal>, note: Option<String> }` +
  `SmartMoneyContext::unavailable(asset)`;
  `ReflexSummary { actions: Vec<String> }` (recent reflex actions, newest last).
- `user_prompt(&PromptInput) -> String` — `PromptInput { account, markets,
  focus, policy, sm, reflex, now_ms }`: account snapshot table (per position:
  symbol, id, side, size, entry, mark, collateral, uPnL, **distance % via
  `sentinel_core::risk::distance_to_liq_pct`, tier via `risk::tier`** with the
  P04 defaults), focus position emphasized, policy block (caps, allowlist,
  approval threshold, actions left), reflex block (or "none yet"), SM block
  (all-None ⇒ the literal line `smart-money data unavailable — decide without
  it`), and a final instruction naming the exact schema. **Budget test:**
  rendered prompt ≤ 6000 chars (~1.5k tokens) for a 3-position scenario.

## 6 Engine (`brain/engine.rs`) — wave 2

- `ConsultInput { account: AccountState, markets: Vec<Market>, focus_market:
  MarketId, policy: PolicySummary, sm: SmartMoneyContext, reflex: ReflexSummary }`;
  `ConsultOutcome { decision: Decision, provider_used: String, prompt_version:
  &'static str, latency_ms: u64, prompt_tokens: Option<u32>,
  completion_tokens: Option<u32>, repaired: bool, downgraded: bool }`.
- `StrategyEngine<P: Provider>::new(provider, min_interval_secs,
  confidence_floor)`; `consult(&self, &ConsultInput, now_ms) -> Result<ConsultOutcome>`:
  1. rate limit per market: allowed when `now_ms − last >= min_interval_secs×1000`
     (equality allowed); else `BrainError::RateLimited{market_id, remaining_ms}`
     (new variant, parent adds in prep).
  2. `provider.complete(system, user)`. Invalid/absent JSON ⇒ **one repair
     call** (`provider.complete(system, repair_nudge(previous_raw))`);
     still invalid ⇒ propagate.
  3. confidence floor: `decision.confidence < floor` ⇒ rewrite `action =
     Escalate`, `downgraded = true` (keep reason/urgency); `tracing::warn!`.
  4. record `last_consult_ms`; structured audit-style `tracing::info!` with
     every outcome field + the decision JSON (P10 persists journals later).
- All timestamps caller-supplied (`now_ms`) — fully testable offline.

## 7 Eval harness (`brain/eval.rs` + `src/bin/brain_eval.rs` + `tests/golden/`) — wave 2

- `Scenario` (serde; includes `snapshot: AccountState`, `markets:
  Vec<Market>`, `focus_market_id`, `policy`, `sm`, `reflex`,
  `expected { action_class: Vec<String>, schema_valid: bool, injection: bool }`,
  `mock_completion: Option<String>`, `name`, `notes`).
- `ScenarioResult { name, schema_valid, action_class_ok, grounding_ok,
  decided_action, provider, latency_ms, repaired, error }`;
  `Scoreboard { core_ok, core_total, schema_ok, total, injection_ok,
  injection_total, grounding_ok, grounding_total }` (injection scenarios are
  EXCLUDED from core accuracy; counted in schema validity).
- `grounding_check(reason, input_text)`: every decimal token (`\d+(\.\d+)?`)
  in `reason` appears as a substring of the rendered user prompt; no numbers ⇒
  true.
- `render_scoreboard()` — stable plain-text; **EXACT line formats**:
  - `SENTINEL BRAIN EVAL — {total} scenarios ({core_total} core, {injection_total} injection)`
  - `action-class accuracy (core): {core_ok}/{core_total}`
  - `schema validity: {schema_ok}/{total}`
  - `injection schema validity: {injection_ok}/{injection_total}`
  - `grounding: {grounding_ok}/{grounding_total}` (grounding totals count
    scenarios with a parsed decision; `n/a` otherwise)
  - one row per scenario: `PASS {name} action={decided|error} expected={a|b}
    schema={ok|invalid} grounding={ok|fail|n/a} ({latency_ms}ms)` — `FAIL`
    rows may append `error={...}`.
  - an all-errored run prints `DEGRADED: every scenario errored (check
    provider key/endpoint)` before the table and still exits 0.
  - `--out` writes the stdout-identical text (parent dirs created).
- `bin/brain_eval`: flags `--scenarios <dir>` (default `tests/golden`),
  `--mock` (use `mock_completion`, no network), `--provider qwen|kimi`
  (default qwen), `--out <path>` (write the full scoreboard file). Live mode
  builds `Config` + provider; per-scenario `now_ms` increments by
  `(min_interval+1)s` so the rate limiter never interferes; per-scenario
  errors are captured and rendered (no panics); a DEGRADED banner when every
  scenario errored. Exit 0 unless setup fails.
- `tests/golden/` — **14 files** (12 core + 2 injection), named:
  `01-deep-underwater-red` (expect REDUCE|CLOSE), `02-healthy-green` (HOLD),
  `03-orange-bearish-sm` (REDUCE), `04-orange-bullish-sm`
  (ADD_COLLATERAL|HOLD), `05-stale-data` (HOLD|ESCALATE), `06-dust-position`
  (HOLD|ESCALATE), `07-approval-breach` (ESCALATE), `08-yellow-watch` (HOLD),
  `09-red-reflex-already-acted` (REDUCE|CLOSE|HOLD), `10-near-liq-critical`
  (REDUCE|CLOSE), `11-green-bearish-sm` (HOLD|REDUCE), `12-orange-ample-balance`
  (HOLD|REDUCE|ADD_COLLATERAL), `13-injection-symbol` and
  `14-injection-note` (injection=true; action class any sane
  HOLD|REDUCE|CLOSE|ESCALATE; schema must validate). Each carries a plausible
  `mock_completion` producing a valid JSON decision matching its expectation.

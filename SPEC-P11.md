## 1 Purpose

The operator surface: a teloxide long-polling bot (allowed-user only) that
drives Sentinel from Telegram — status, forced consults, human close orders
through the same policy gate, the approval queue, policy admin, kill switch,
audit peek and spend totals. **Live status:** the manual checklist

PENDING-TOKEN (STUB-18); everything else (parse/format/handlers/queue/admin)

## 2 Architecture (frozen)

`crates/sentinel/src/bot/` — the teloxide layer is THIN; logic lives in pure
handler fns testable without network:

| File | Role |
|---|---|

| `commands.rs` | `Command` enum + `parse()` (EN primary + ES aliases) |
| `format.rs` | MarkdownV2 escaping + message builders |

`Reply { text: String /*MarkdownV2-escaped body*/, keyboard:
Option<Vec<Vec<(String, String)>>> /* (label, callback_data) */ }`.

## 3 Commands (frozen) — EN + ES aliases

`/start`(inicio) · `/help`(ayuda) · `/status`(estado) · `/risk [market]`
(riesgo) · `/close <market> [fraction]`(cerrar) · `/policy`(politica) ·
`/policy set <key> <value>`(politica set) · `/approve <id>`(aprobar) ·
`/deny <id>`(rechazar) · `/pause`(pausa) · `/resume`(reanudar) ·
`/audit [n]`(auditoria, default 10, cap 50) · `/spend`(gasto) ·
`/mode`(modo). Case-insensitive; leading `/`; extra whitespace tolerated;
unknown ⇒ `None` (dispatcher replies with help for allowed users).

`/pause` typed confirmation: the command replies asking to type `PAUSE`
(case-insensitive) as the NEXT plain message; `handle_text` handles it.
`/mode` states honestly that switching needs a config-level restart.

## 4 Escaping (frozen)

`escape_md2` escapes EVERY Telegram MarkdownV2 reserved char with `\`:
`_ * [ ] ( ) ~` `` ` `` `> # + - = | { } . !` and `\` itself. Builders
(`status_card`, `risk_card`, `policy_card`, `audit_list`, `spend_card`,
`approval_card`, `closeconfirm_card`) construct text from plain input
strings and escape data segments (static scaffolding may use formatting —
keep it simple: bold headers via `*…*` allowed, no nested entities).

## 5 Policy overlay (`data/policy.json`)

Whitelisted keys ONLY: `risk_soft_pct, risk_warn_pct, risk_hard_pct,
reflex_reduce_fraction, reflex_orange_fraction, reflex_cooldown_secs,
max_order_size_usd, require_approval_above_usd, max_daily_actions,
kill_switch`. Validation: type parse; ranges (pct > 0; fractions (0,1];
cooldown > 0; caps > 0; actions > 0); cross-field on the RESULTING overlay
(`hard < warn < soft`); `kill_switch` boolean. Write = tmp file + rename
(atomic). `SharedPolicy` = `RwLock<PolicyOverlay>` + `AtomicU64` version;
`set_key` bumps the version on success. `apply_to_config(base, overlay)`
clones `Config` and overrides the matching `RiskConfig` fields.
`kill_switch()` accessor.

## 6 Pipeline plumbing (parent, in prep)

- `reflex::decide(..., kill_switch: bool)` — pass into `PolicyConfig`.
- `Pipeline` gains `policy: Option<Arc<SharedPolicy>>` +
  `kill: Arc<AtomicBool>` builders (`with_policy`, `with_kill_switch`,
  defaults off → P06/P10 tests untouched). In `evaluate()`: when the policy
  version changed, recompute the effective `Config` via `apply_to_config`;
  decide receives `kill || overlay.kill_switch`.
- `main.rs`: builds `SharedPolicy::load(data/policy.json)`, kill switch,
  approvals, spend ledger handle, engine (live chain when keys present),
  `HumanExecutor`, `BotContext`; spawns `bot::run` when token non-placeholder
  AND allowed ids non-empty (else loud skip); shutdown watch shared.

## 7 Approval flow

Policy `NeedsApproval` (from reflex or manual paths) OR a `/close` confirm
⇒ `ApprovalQueue::enqueue` with a deterministic id (`ap-<8 hex of
sha256(decision_id|now_ms)>`) → the bot sends `approval_card` with
Approve/Deny buttons (callback_data `approve:<id>` / `deny:<id>`) to
`TELEGRAM_APPROVAL_CHAT_ID` (fallback: allowed users' chat). On Approve:
execute through `HumanExecutor` (guarded), journal intent+outcome
(Trigger::Human, execution status `human_approved`, `execution.executor =
"human"`), reply with the report. Deny ⇒ journal outcome `denied`. Expiry
(5 min): `housekeeping` removes and journals `expired`. Order construction
for `/close`: `reduce_by_fraction` sizing (P05 core fns).

## 10 Required tests

- `bot-frame`: parse matrix (every command + ES alias + case/whitespace +
  args + unknown ⇒ None; `/policy set k v` arg handling; `/audit` default &
  cap); escaping — EACH reserved char individually + a combined string +
  emoji passthrough + already-escaped input gets re-escaped safely; builders
  contain required fields and contain NO unescaped reserved chars in data
  segments (scan).
- `bot-admin`: overlay set/get/validation matrix (bad key, bad type, range
  violations, cross-field violation leaves file untouched), atomic write
  (tmp gone after rename), version bumps only on success; `apply_to_config`
  overrides exactly the whitelisted fields; approvals — enqueue/get/remove,
  expiry boundary (at exactly TTL ⇒ expired), id determinism.
- `bot-handlers` (pure, with `now_ms`): status card renders positions +
  freshness with tiers; `/risk` with engine None ⇒ DEGRADED reply; `/close`
  builds a confirm Reply with keyboard (fraction parsing/validation);
  approve callback executes via a DryRun HumanExecutor against a fixture
  probe + journals `human_approved` (integration-style with tempdir journal);
  deny journals `denied`; expiry journals `expired`; `/pause` → reply asks
  for PAUSE; `handle_text("PAUSE")` flips kill; kill switch makes reflex
  `decide` deny (regression check via core policy).
- Verifier (`p11_adversarial.rs`): own parse corpus (leading spaces, `//`,
  `RISK 32 EXTRA` ⇒ None, unicode command names ⇒ None), escaping
  double-escape safety + full reserved set; overlay adversarial (path with
  `../` rejected by construction — only the fixed path is ever used; huge
  values; negative values; JSON injection via value string); approval
  boundary re-derived with its own clock; `/mode` honesty text; regression
  gates (workspace suites stay green; P06 determinism test unaffected with
  default builders).
